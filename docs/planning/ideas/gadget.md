### Hermes Gadget (https://hermes-agent.nousresearch.com/marketplace/gadget)
**Verdict:** Maybe — a good Hermes platform plugin for ESP32 voice devices, but Studio already has its own MCU device stack, so only worth it if the user owns compatible boards.
**What it is:** A community Hermes Agent platform plugin (by Adolanium, v0.5.0, needs Hermes 0.21.6+). It adds a `gadget` gateway platform so small ESP32 boards with screen, mic and speaker can talk to Hermes (hold button, ask, hear answer). It adds agent tools `gadget_devices`, `gadget_display`, `gadget_action` (LEDs, relays, camera), a `hermes gadget` CLI, OTA firmware updates, a dashboard tab and a Desktop page. Firmware (C/ESP-IDF), Linux sim and Python SDK are in the same repo.
**Already in Studio/Hermes?** Partly. Studio has `packages/mcu` (ESP32-C3 v1/v2, S3 Cardputer, StackChan plan), OTA endpoints `/api/studio/mcu/firmware/*`, `McuDevicesPanel.vue` and `docs/mcu-webhook-events.md`. That is a separate, Studio-specific protocol. Gadget does not replace it; it is a rival path to the same goal. Studio already has a Hermes plugin manager (`services/plugins/plugins.ts`).
**How to use it in Hermes Studio:** On the Hermes host (Unraid container): `hermes plugins install gadget` then `hermes gadget setup`. Publish port 8765 only on the LAN (or behind a reverse proxy with TLS). Pair each device with `hermes gadget pair`. Studio's plugin page should then list it; Gadget chats show up as normal DM sessions.
**How to use it in herdr:** Not relevant. It is a voice/hardware channel, not a terminal/agent-pane tool. At most, a gadget DM session could appear as a herdr space via the existing chat sync.
**How to integrate it properly (build work):**
- Docs only (small): add a "Gadget plugin" note beside the MCU docs saying when to pick it vs Studio's MCU stack.
- Settings (small): show Gadget plugin status and a link to its dashboard tab in the Connections page next to `McuDevicesPanel`.
- Optional (medium): read `hermes gadget devices` output to show Gadget devices in `McuDevicesPanel`; approval hand-off already exists in Hermes (allow once/deny).
- Docker (small): expose/map port 8765 in the Unraid template if enabled.
**Risks:** Listens on 0.0.0.0:8765 with plain `ws://` unless TLS is set up; keep it LAN-only. Pairing code required; never set `GADGET_ALLOW_ALL_USERS` outside dev. STT/TTS may go to cloud providers. Two device ecosystems to maintain. Third-party code (~9k lines Python in plugin/) not audited by me beyond reading the page and layout.
