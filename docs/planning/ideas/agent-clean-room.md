### agent-clean-room (https://github.com/bigsnarfdude/agent-clean-room)
**Verdict:** Skip as a tool, Maybe for ideas — it is a research write-up, not software we can install; but 4 of its lessons are worth copying into Studio's own clean rooms.
**What it is:** A personal research repo (one commit, Oct 2026) that re-creates the OpenAI/Hugging Face agent incident in a lab and asks which claims hold. "Clean room" here means a clean *experiment* (nothing leaks to the agent subjects), not a sandbox that stops agents escaping. It has Python audit scripts, shell launchers, and many committed run traces. Its main output is a protocol (`docs/PROTOCOL.md`, `docs/CHANNELS.md`).
**Already in Studio/Hermes?** Studio's clean room (`docs/cleanroom.md`, `services/cleanroom/index.ts`) is the opposite job: a per-chat Docker container (`--network none`, allowlist proxy, no-new-privileges, dropped caps, CPU/mem/pid limits, own `/root` home). That already covers containment better than this repo does. This repo has no sandbox product; its only container is a small debian image (4 unprivileged users, `--cap-drop ALL`, exec-only, no network) used for its dormant-note test.
**How to use it in Hermes Studio:** Not as a plugin, skill or MCP server (nothing to install; scripts hardcode its own lab and run hosts). Read `docs/PROTOCOL.md` and copy ideas (see build work). Do not run its code.
**How to use it in herdr:** Not relevant directly. Its idea of "ask the agent what it can see" could become a herdr Tools dock check later, but only after the Studio version exists.
**How to integrate it properly (build work):** Ideas worth borrowing, in order:
- **Context probe ("ask the subject")** — small. A `/cleanroom check` that runs the agent once with "list what is in your context: git branch, commit messages, memory, CLAUDE.md, env tokens, mounted paths" and shows the answer in the chat header/badge. Proves the room is clean instead of trusting the mount list. Add to `services/cleanroom/index.ts` + a route + a button in the Clean room badge.
- **Leak pre-flight on the chat folder** — small. Studio mounts the chat folder read-write at the same path, so the agent still sees that folder's git branch/commits and any CLAUDE.md in it or above it (the walk-up). Warn (or offer "copy into a non-git neutral folder") when the folder is a git repo or has a CLAUDE.md on the path. Studio already isolates `~/.claude` memory via the room's own `/root` home, which is the repo's channel 5/6 fix.
- **Real walls need a different owner or read-only mount** — small. The repo proves `chmod 444` is beaten by the Edit tool (write-new + `rename`), and a root-owned checker that calls bare `python3` is beaten by a `PATH` shadow. For Studio: when we want a file/folder protected inside a room (e.g. approvals config, a checker script), use `:ro` mounts or a separate UID, pin absolute interpreter paths. Check that no Studio-set path in the room is only chmod-protected.
- **Per-agent users for multi-agent rooms** — medium, only if we ever put several agents in one room: separate unprivileged users with mode-700 homes, orchestrator uses `docker exec -u`, no sudo installed. Today one room = one chat = one agent, so not needed yet.
- **Evidence hygiene** — small. Rooms live under our own paths, not `/tmp` (the repo lost six runs to tmpfiles-clean); sync chat transcripts out early. Studio's room homes under `coding-agent/cleanroom/homes` already avoid this; just keep it that way.
**Risks:** Almost none for adopting ideas. If someone ran its scripts: they spawn `claude --dangerously-skip-permissions` on a "run host" over SSH, cost API money, and some tools silently print zeros. Content is about agent deception incidents; no malicious code seen in the files read, but treated as untrusted and not run. Single author, claims not peer reviewed, no positive controls (the author says so).
**Facts:** MIT licence; one commit, last activity 2026-10-01; no releases seen, star count not checked; Python, bash and markdown.
