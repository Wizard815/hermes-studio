### Phone Harness (https://hermes-agent.nousresearch.com/marketplace/phone-harness)
**Verdict:** Maybe — a nice way to let agents drive the Android devices Studio already connects to, but Studio's own adb layer covers most of it; try the plugin first, build little.
**What it is:** A Hermes plugin (v0.1.0, needs Hermes 0.21.6+) that adds one tool, `phone_exec`. The model writes a short Python script using phone helpers (tap, type, scroll, screenshot, read screen); the plugin runs it and returns the output. Android works over adb (screenshots + accessibility tree for text); iPhone works through Mac iPhone Mirroring; there is also a paid hosted "Phone Harness Cloud". It also ships a skill (`phone-harness:phone-harness`), and an MCP endpoint (cloud only).
**Already in Studio/Hermes?** Studio's Android page (docs/android-devices.md) already does adb, emulator (live gRPC stream), Wi-Fi/USB phones, BlueStacks, APK install, remote adb server and a Termux bridge. But that is for a human at the screen; agents only get raw `adb` in the terminal. No agent-facing "see screen and tap" tool, no accessibility-tree reading. iPhone and cloud phones are not covered.
**How to use it in Hermes Studio:** 1) Make sure the Hermes container can reach the same adb server (set `ANDROID_ADB_SERVER_ADDRESS` or connect the device in the container; Studio keeps adb keys in `hermes_data/android`). 2) `hermes plugins install phone-harness` inside the Hermes profile, start a new chat, restart the gateway. 3) Keep approvals on "ask"; leave telemetry off. 4) Turn it off for Mattermost/Home Assistant toolsets with `hermes tools`, since it is added to every platform with a saved tool selection. Skip iPhone and cloud: Unraid is not a Mac.
**How to use it in herdr:** Not directly. It is a Hermes plugin, so it works in any chat that uses Hermes, including the herdr-synced one. Coding agents (Claude Code, Codex) could use the CLI + `phone-harness skill` instead; that is optional.
**How to integrate it properly (build work):**
- Small: docs note plus a Docker env var so the Hermes process uses the Studio-managed adb server and keys.
- Small/medium: Android page shows "agent is controlling this device" and an agent lock/stop button, so the human and the agent do not fight over taps.
- Medium: a Studio-native `android_exec` tool (MCP or Hermes plugin) reusing `services/android/{adb,input}.ts`, with screenshots and the approval flow (ask/guarded/auto). This would work for every agent through the gateway, not only Hermes, and avoids running a second adb stack.
- Medium (optional): a clean-room image with phone-harness CLI + adb for coding agents.
**Risks:** Runs model-written Python on the host with the user's permissions; its "phone-only" auto-approve classifier is a bypassable heuristic, so use ask mode or run it in a clean room. Real phone means real accounts (messages, purchases); the plugin says it won't type passwords/2FA but do not rely on that. Cloud mode streams the screen and uploads files to a third party and bills per minute. Optional PostHog telemetry can include scripts and output (off by default in Hermes). Screenshots land in the temp folder. Young plugin (v0.1.0), single author.
**Facts:** Repo github.com/phone-harness/phone-harness, MIT (the marketplace page does not state it; the repo does). About 5.3k stars, 556 forks, 149 commits, no GitHub releases seen. Python (3.12, uv). Plugin path `integrations/hermes`. Source repo was read via page summary only, not cloned.
