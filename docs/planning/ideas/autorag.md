### AutoRAG plugin for Hermes (https://hermes-agent.nousresearch.com/marketplace/autorag)
**Verdict:** Maybe — a good local "search my files and chat archives" tool, but it overlaps the parked LLM-wiki idea and is not yet proven on Linux/Docker.
**What it is:** A Hermes Agent plugin (Agent Plugins v1: `plugin.json` + `mcp.json` + 4 skills + a dashboard tab + a desktop search pane) from Marker-Inc-Korea. It starts a local MCP server (`@autorag/librarian@2.13.12` via `npx`) that indexes local files (PDF, DOCX, PPTX, XLSX, CSV, Markdown, email, HWP) and chat/mail archives (Slack, Discord, Telegram, WhatsApp, KakaoTalk, Notion, Obsidian, GitHub, RSS). Search is hybrid (BM25 + dense Qwen3-Embedding-0.6B + sparse) and returns cited chunks. Hermes keeps its own model; AutoRAG only supplies retrieval.
**Already in Studio/Hermes?** No file/archive search. Studio has a Memory provider picker (Honcho, Mem0, RetainDB, ByteRover; docs/hermes-integrations.md) but that is agent memory, not document RAG. Overlap: plan.md line 47 parks an "LLM wiki memory provider" (Wizard815/LLM-will-remember-this on Unraid). Both give Hermes long-term recall from text. The wiki idea is a curated, agent-written memory; AutoRAG is a read-only index of existing files and chats. They can coexist (wiki = what the agent learned, AutoRAG = what you already have). If only one is built, the wiki provider fits Studio's Memory page better; AutoRAG fits as a plugin.
**How to use it in Hermes Studio:** On the Unraid host/container where Hermes runs: `hermes plugins install autorag && hermes plugins enable autorag`, then ask Hermes "set up AutoRAG for /mnt/user/<share>". It needs Node 24+, Hermes >= 0.22.3 with the `mcp` extra, and mounted folders (the Hermes container needs the shares as volumes, ideally read-only). Persist the AutoRAG workspace on a volume; the first index downloads ~1.5 GB of models and runs on CPU (fine on NUC, slow for big folders). Studio's Hermes skills/plugins page should then show it; check that the MCP tools appear after `/reload-mcp`.
**How to use it in herdr:** Mostly not relevant. Coding agents in herdr spaces could call it only if the same MCP server is added to their config; it would be a "search my notes/docs" helper, not terminal work. Optional: expose it as an MCP server to Claude Code/Codex through the model gateway's MCP settings.
**How to integrate it properly (build work):**
- Small: docs page + a one-click "Install AutoRAG" button on the Studio plugins page (runs the two `hermes plugins` commands); Docker image note to include Node 24 and a data volume.
- Small: Studio Settings field for AUTORAG_SEARCH_PATHS / read-only flag (AUTORAG_MCP_READ_ONLY) written to the plugin env.
- Medium (optional): a Studio "Search" panel or herdr Tools dock tab calling the AutoRAG MCP/dashboard API (the plugin ships `dashboard/plugin_api.py` and a manifest, which Studio could embed instead of building UI).
- Medium (optional): clean-room support: mount AutoRAG as an MCP server into the chat container only on opt-in, since it exposes file contents.
**Risks:** Page lists macOS only; Linux/Docker/Unraid untested by the author. Heavy: 1.5 GB models, optional Rust compile (~6 min). Runs `npx -y` with `npm_config_allow_remote=all`, pulling a pinned npm package at runtime (supply-chain surface; pin and mirror it). Privacy: chat archives (WhatsApp, Slack, mail) become searchable and snippets go to whatever model provider/gateway the chat uses, so cloud models see them; keep it off clean rooms and off auto-approval chats. Automations it can create write scripts and Hermes cron jobs. Very new (v1.0.0 plugin), so expect churn. No telemetry claimed.
