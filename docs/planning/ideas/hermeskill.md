### Hermeskill (https://github.com/theopitori/hermeskill)
**Verdict:** Maybe — a real Hermes plugin that adds loop, cost and time kill-switches Studio lacks, but it is a brand-new one-commit project, so trial it on one Hermes profile before wiring in.
**What it is:** A Python plugin for Hermes Agent that watches every tool call and LLM turn in-process. When the agent loops, spends too much, runs too long or calls a tool outside its scope, it blocks all further tool calls and writes a "death certificate" (JSON plus a terminal box, saved in `~/.hermeskill/kills/`). It also has a "loop steer" (a nudge before a kill), a `hermeskill monitor` terminal view, an optional process supervisor (SIGTERM then SIGKILL), and an optional FastAPI + Postgres control plane for history and manual kills.
**Already in Studio/Hermes?** Partly. Studio has approvals (ask / guarded / auto) in `coding-agents/services/approval-policy.ts`, a write-gate for Hermes memory/skills writes (`hermes/services/write-gate`), and approval timeouts plus run idle timeouts in `run-manager.ts`. Those ask a human about risky single actions. Studio has no loop detection, no per-run cost cap, and no "kill with a report" step. Hermeskill is complementary (runaway control), not a replacement for approvals. It only covers Hermes Agent, not Claude Code, Codex, etc.
**How to use it in Hermes Studio:**
- Install into the Hermes venv that Studio launches (`uv tool install hermes-agent --with hermeskill-hermes`, or `uv pip install --python <hermes venv>/bin/python hermeskill-hermes`), then `hermeskill enable-hermes` (sets `plugins.enabled` in the Hermes profile config). Do this in the Hermes Docker image, not on the Unraid host.
- Start in local mode only (no control plane, no network). Pick a policy with `HERMESKILL_POLICY` (`coding-default`, `strict`, `permissive`).
- Mount `~/.hermeskill/kills/` as a volume so certificates survive container restarts.
**How to use it in herdr:** Not directly. Herdr is a terminal multiplexer; Hermes chats already show up there as spaces, so a kill message appears in the pane like any block message. Optionally run `hermeskill monitor` in a herdr pane. Nothing to build in herdr itself.
**How to integrate it properly (build work):**
- Small: bake the plugin into the Hermes image/profile setup and add a settings toggle plus policy dropdown (Hermes settings page, `hermes/controllers/config.ts`) that writes the env var and plugin flag.
- Medium: a "Kills" list in Studio that reads `~/.hermeskill/kills/*.json` and shows the reason/cost; link each to its chat; raise an Inbox/Agent work notification when one appears.
- Small: show the "hermeskill apoptosis: ..." block message clearly in the chat UI instead of as a generic tool error.
- Large, skip for now: the control plane (needs Postgres) and a cost cap for non-Hermes agents; for those, put loop/cost limits in the model gateway instead.
**Risks:** Very young: single commit (last 2026-06-06), no releases seen, small community; check it is on PyPI before relying on the `uv tool` path, otherwise install from git. Stops only at tool boundaries (cannot stop a stuck synchronous call; the L3 supervisor is opt-in and does not apply to Studio's embedded bridge). Could false-kill legitimate repeated calls; tune policy and use grants. Local mode makes no network calls (the HTTP client is only for the optional control plane); I did not run it. Plugin runs inside the Hermes process with full access, so pin the version and read the code before updating. Needs Python 3.11+ matching Hermes.
**Facts:** MIT licence; Python (uv workspace: hermeskill-sdk, hermeskill-hermes, control-plane); 1 commit visible, last 2026-06-06; stars/releases not checked; docs include a real GPT-4o kill transcript.
